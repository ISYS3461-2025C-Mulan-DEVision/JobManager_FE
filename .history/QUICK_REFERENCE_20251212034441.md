# Quick Reference: Component Architecture

## 🎯 When to Use Each Component Type

### Headless Components (`/components/headless/`)
**Use when:**
- You need reusable logic without UI coupling
- Multiple features need the same behavior with different UIs
- You want to test logic separately from presentation

**Examples:**
- `HeadlessForm` - Form state management
- `HeadlessTable` - Table sorting, pagination, filtering
- `HeadlessModal` - Modal open/close logic

**Pattern:**
```tsx
<HeadlessComponent>
  {(logicProps) => <YourCustomUI {...logicProps} />}
</HeadlessComponent>
```

---

### UI Components (`/components/ui/`)
**Use when:**
- Creating reusable design system elements
- Building atomic UI components
- Styling should be consistent across the app

**Examples:**
- `Button` - Styled button with variants
- `Input` - Form input with label/error
- `Card` - Container with consistent styling

**Pattern:**
```tsx
<Button variant="primary" size="lg">
  Click me
</Button>
```

---

### Feature Components (`/components/feature/`)
**Use when:**
- Implementing a specific business feature
- Combining headless logic with UI components
- Managing feature-specific state and API calls

**Examples:**
- `CompanyLogin` - Login functionality
- `JobTable` - Job listing with filters
- `UserProfile` - User profile management

**Pattern:**
```tsx
// Main component
export const FeatureName = () => {
  const { data, isLoading } = useFeature();
  
  return (
    <HeadlessComponent>
      {(props) => <FeatureUI {...props} data={data} />}
    </HeadlessComponent>
  );
};
```

**Structure:**
```
FeatureName/
├── index.ts              # Exports
├── FeatureName.tsx       # Main (composition)
├── FeatureNameUI.tsx     # UI layer
├── useFeatureName.ts     # Business logic
├── types.ts              # Types
└── api/
    └── service.ts        # API calls
```

## 📊 Component Hierarchy

```
┌─────────────────────────────────────┐
│           Pages (Routes)            │
│   - LoginPage, HomePage, etc.       │
│   - Minimal logic, route handling   │
└──────────────┬──────────────────────┘
               │ imports
               ▼
┌─────────────────────────────────────┐
│      Feature Components             │
│   - CompanyLogin, JobTable          │
│   - Business logic + composition    │
└──────┬──────────────────────┬───────┘
       │                      │
       │ composes             │ composes
       ▼                      ▼
┌──────────────┐      ┌──────────────┐
│  Headless    │      │  UI          │
│  Components  │      │  Components  │
│              │      │              │
│  - Form      │      │  - Button    │
│  - Table     │      │  - Input     │
│  - Modal     │      │  - Card      │
└──────────────┘      └──────────────┘
```

## 🔄 Data Flow

```
User Action
    │
    ▼
┌─────────────────┐
│  UI Component   │ ◄─── Styling, presentation
└────────┬────────┘
         │ event
         ▼
┌─────────────────┐
│ Feature Logic   │ ◄─── Business logic hook
└────────┬────────┘      (useFeature)
         │ calls
         ▼
┌─────────────────┐
│  API Service    │ ◄─── HTTP requests
└────────┬────────┘
         │ response
         ▼
┌─────────────────┐
│  Redux Store    │ ◄─── Global state
└─────────────────┘      (optional)
```

## 💡 Decision Tree

**Need reusable logic?**
- ✅ Create Headless Component
- ❌ Use existing or create Feature hook

**Need reusable UI?**
- ✅ Create UI Component
- ❌ Create component-specific UI

**Building a feature?**
- ✅ Create Feature Component
- Structure: Main → UI → Hook → API

**Creating a page?**
- ✅ Compose Feature Components
- Keep logic minimal

## 🎨 Styling Approach

### UI Components
```tsx
// Tailwind classes, variants, responsive
<Button 
  variant="primary" 
  size="lg"
  className="custom-class"
/>
```

### Feature Components
```tsx
// Composition with UI components
<Card>
  <CardHeader>Title</CardHeader>
  <CardBody>
    <Input label="Name" />
    <Button>Submit</Button>
  </CardBody>
</Card>
```

### Headless Components
```tsx
// No styling, pure logic
<HeadlessForm onSubmit={submit}>
  {({ values, handleChange }) => (
    // You provide all UI
    <div className="...">
      <input 
        value={values.email} 
        onChange={handleChange} 
      />
    </div>
  )}
</HeadlessForm>
```

## 🧪 Testing Strategy

**Headless Components**
- Unit test pure logic
- Test state management
- No DOM testing needed

**UI Components**
- Visual regression tests
- Accessibility tests
- Variant/prop combinations

**Feature Components**
- Integration tests
- User flow tests
- Mock API calls

## 🚀 Example: Creating Login Feature

```bash
# 1. Create structure
mkdir -p src/components/feature/Auth/Login/{api,hooks,ui}

# 2. Create files
types.ts          # LoginPayload, LoginResponse
api/service.ts    # login(), logout()
hooks/useLogin.ts # Business logic
LoginUI.tsx       # UI composition
Login.tsx         # Main component
index.ts          # Exports

# 3. Implement
Login.tsx:
  - Use useLogin() hook
  - Compose with HeadlessForm
  - Pass props to LoginUI

# 4. Use in page
import { Login } from "@/components/feature";
<Login />
```
