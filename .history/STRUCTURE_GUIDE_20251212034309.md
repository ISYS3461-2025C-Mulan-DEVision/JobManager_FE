# Project Structure Guide

## 📁 Directory Overview

```
src/
├── components/           # All reusable components
│   ├── headless/        # Logic-only components (no UI)
│   ├── ui/              # Styled presentational components
│   └── feature/         # Feature-specific components
├── hooks/               # Global custom hooks
├── layout/              # Layout components (Header, Sidebar, etc.)
├── pages/               # Page components (Routes)
├── services/            # API services and HTTP client
├── store/               # Redux store configuration
├── types/               # Global TypeScript types
└── utils/               # Utility functions and helpers
```

## 🔧 Component Architecture Layers

### 1. Headless Components (`/components/headless/`)
**Purpose**: Provide reusable logic without any UI

**When to create**:
- Reusable stateful logic (forms, tables, modals)
- Logic that can be used with different UIs
- Complex state management that multiple features need

**Example**: `HeadlessForm`
```tsx
// Provides form logic but no UI
<HeadlessForm onSubmit={handleSubmit}>
  {({ values, handleChange }) => (
    // Your custom UI here
  )}
</HeadlessForm>
```

### 2. UI Components (`/components/ui/`)
**Purpose**: Presentational components with consistent styling

**When to create**:
- Reusable design system elements
- Components used across multiple features
- Atomic UI components (buttons, inputs, cards)

**Example**: `Button`
```tsx
<Button variant="primary" size="lg" isLoading={loading}>
  Submit
</Button>
```

### 3. Feature Components (`/components/feature/`)
**Purpose**: Business logic + composition of headless + UI

**Structure**:
```
FeatureName/
├── index.ts                    # Public exports
├── FeatureName.tsx            # Main component (composition)
├── FeatureNameUI.tsx          # UI composition layer
├── useFeatureName.ts          # Business logic hook
├── types.ts                   # Feature-specific types
└── api/
    └── featureService.ts      # API calls
```

**Example**: CompanyLogin
```tsx
// CompanyLogin.tsx - Composition layer
export const CompanyLogin = () => {
  const { login, isLoading, error } = useCompanyLogin();
  
  return (
    <HeadlessForm onSubmit={login} validate={validateLoginForm}>
      {(formProps) => (
        <CompanyLoginForm {...formProps} isLoading={isLoading} error={error} />
      )}
    </HeadlessForm>
  );
};
```

## 📐 File Naming Conventions

| Type | Convention | Example |
|------|-----------|---------|
| Components | PascalCase | `Button.tsx`, `CompanyLogin.tsx` |
| Hooks | camelCase + `use` prefix | `useCompanyLogin.ts`, `useDebounce.ts` |
| Types | PascalCase | `types.ts`, `LoginPayload` |
| Utils | camelCase | `helpers.ts`, `validators.ts` |
| Constants | UPPER_SNAKE_CASE | `API_BASE_URL` |
| Files | PascalCase for components, camelCase for others | - |

## 🎯 Import Path Aliases

Use path aliases for cleaner imports:

```tsx
// ❌ Avoid relative imports
import { Button } from "../../../components/ui/Button";

// ✅ Use path aliases
import { Button } from "@/components/ui";
```

**Available aliases**:
- `@/` → `src/`
- `@/components/*` → `src/components/*`
- `@/hooks/*` → `src/hooks/*`
- `@/types/*` → `src/types/*`
- `@/utils/*` → `src/utils/*`
- `@/services/*` → `src/services/*`
- `@/store/*` → `src/store/*`

## 🔄 Data Flow Pattern

```
┌──────────────────────────────────────────────┐
│  Page Component                              │
│  - Route handler                             │
│  - Minimal logic                             │
└──────────────┬───────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────────┐
│  Feature Component                           │
│  - useFeature() hook (business logic)        │
│  - Compose headless + UI                     │
└──────────────┬───────────────────────────────┘
               │
       ┌───────┴────────┐
       ▼                ▼
┌─────────────┐  ┌─────────────┐
│  Headless   │  │  UI         │
│  Component  │  │  Component  │
│  (Logic)    │  │  (Styling)  │
└─────────────┘  └─────────────┘
```

## 🛠️ Creating a New Feature

### Step-by-step guide:

1. **Create feature directory**:
```bash
mkdir -p src/components/feature/FeatureName
cd src/components/feature/FeatureName
```

2. **Create files**:
```bash
touch index.ts FeatureName.tsx FeatureNameUI.tsx useFeatureName.ts types.ts
mkdir api
touch api/featureService.ts
```

3. **Implement types** (`types.ts`):
```tsx
export interface FeatureData {
  id: string;
  name: string;
}

export interface FeaturePayload {
  // Request data
}
```

4. **Implement API service** (`api/featureService.ts`):
```tsx
import { httpClient } from "@/services/httpClient";

export const featureService = {
  getData: () => httpClient.get("/endpoint"),
  createData: (payload) => httpClient.post("/endpoint", payload),
};
```

5. **Implement business logic hook** (`useFeatureName.ts`):
```tsx
import { useState } from "react";
import { featureService } from "./api/featureService";

export const useFeatureName = () => {
  const [isLoading, setIsLoading] = useState(false);
  
  const fetchData = async () => {
    setIsLoading(true);
    try {
      const data = await featureService.getData();
      return data;
    } finally {
      setIsLoading(false);
    }
  };
  
  return { fetchData, isLoading };
};
```

6. **Implement UI composition** (`FeatureNameUI.tsx`):
```tsx
import { Input, Button } from "@/components/ui";

export const FeatureNameUI = ({ /* props */ }) => {
  return (
    <div>
      {/* Your UI composition */}
    </div>
  );
};
```

7. **Implement main component** (`FeatureName.tsx`):
```tsx
import { useFeatureName } from "./useFeatureName";
import { FeatureNameUI } from "./FeatureNameUI";

export const FeatureName = () => {
  const { fetchData, isLoading } = useFeatureName();
  
  return <FeatureNameUI onFetch={fetchData} isLoading={isLoading} />;
};
```

8. **Export** (`index.ts`):
```tsx
export { FeatureName } from "./FeatureName";
export type * from "./types";
```

## 📦 Module Exports

### Barrel Exports
Each directory should have an `index.ts` that exports its public API:

```tsx
// components/ui/index.ts
export * from "./Button";
export * from "./Input";
export * from "./Card";
```

**Benefits**:
- Clean imports
- Single source of truth
- Easy refactoring

## 🧪 Testing Strategy

### Unit Tests
- Headless components (pure logic)
- Utility functions
- Custom hooks

### Integration Tests
- Feature components
- User flows
- API interactions

### E2E Tests
- Critical user journeys
- Authentication flows

## 🎨 Styling Guidelines

1. **Use Tailwind CSS** for utility-first styling
2. **Extract reusable variants** into UI components
3. **Use `clsx`** for conditional classes:
```tsx
className={clsx(
  "base-class",
  isActive && "active-class",
  className
)}
```

## 🔐 Type Safety

1. **Define interfaces** for all props
2. **Use generics** for reusable components
3. **Avoid `any`** - use `unknown` if type is truly unknown
4. **Export types** from component files
