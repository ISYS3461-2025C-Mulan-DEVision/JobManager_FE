# JobManager Frontend Architecture

## Overview
This project follows a **modularized component architecture** with a **headless UI pattern** for maximum flexibility, reusability, and testability.

## Architecture Principles

### 1. **Separation of Concerns**
- **Headless Components**: Pure logic, no styling
- **UI Components**: Pure presentation, reusable
- **Feature Components**: Business logic + composition

### 2. **Component Hierarchy**

```
┌─────────────────────────────────────────┐
│          Pages (Routes)                 │
│  - Compose features + layout            │
└─────────────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│      Feature Components                 │
│  - Business logic hooks                 │
│  - Compose headless + UI                │
└─────────────────────────────────────────┘
                  │
        ┌─────────┴──────────┐
        ▼                    ▼
┌──────────────┐    ┌──────────────┐
│  Headless    │    │  UI          │
│  Components  │    │  Components  │
│  (Logic)     │    │  (Styling)   │
└──────────────┘    └──────────────┘
```

## Directory Structure

### `/src/components/headless/`
**Pure logic components** that manage state and behavior without any UI.

**Example**: `HeadlessForm`
```tsx
<HeadlessForm onSubmit={handleSubmit}>
  {({ values, handleChange }) => (
    // Your custom UI here
  )}
</HeadlessForm>
```

**Benefits**:
- Logic reusability across different UIs
- Easy to test (no DOM)
- Framework agnostic

### `/src/components/ui/`
**Presentational components** with styling but minimal logic.

**Example**: `Button`, `Input`, `Card`
```tsx
<Button variant="primary" size="lg">
  Click me
</Button>
```

**Benefits**:
- Consistent design system
- Reusable across features
- Easy to style with Tailwind

### `/src/components/features/`
**Feature-specific components** that combine headless logic with UI components.

**Structure**:
```
Feature/
├── index.ts              # Public exports
├── FeatureName.tsx       # Main component
├── FeatureUI.tsx         # UI composition
├── useFeature.ts         # Business logic hook
├── types.ts              # Feature types
└── api/
    └── featureService.ts # API calls
```

**Example**: Authentication Feature
```tsx
// CompanyLogin/CompanyLogin.tsx
export const CompanyLogin = () => {
  const { login, isLoading } = useCompanyLogin();
  
  return (
    <HeadlessForm onSubmit={login}>
      {(formProps) => (
        <CompanyLoginForm {...formProps} isLoading={isLoading} />
      )}
    </HeadlessForm>
  );
};
```

### `/src/hooks/`
**Global custom hooks** for shared functionality.

Examples:
- `useDebounce`: Debounce values
- `useLocalStorage`: Persist state
- `useAuth`: Authentication state

### `/src/types/`
**Global TypeScript definitions** for type safety.

## Design Patterns

### 1. **Headless UI Pattern**

**Problem**: UI components are hard to reuse with different styles.

**Solution**: Separate logic from presentation.

```tsx
// ❌ Tightly coupled
<LoginForm className="..." />

// ✅ Headless pattern
<HeadlessForm onSubmit={login}>
  {({ values, handleChange }) => (
    <YourCustomUI values={values} onChange={handleChange} />
  )}
</HeadlessForm>
```

### 2. **Render Props Pattern**

Headless components use render props to inject logic:

```tsx
interface HeadlessFormProps<T> {
  children: (props: FormRenderProps<T>) => React.ReactNode;
}
```

### 3. **Custom Hooks for Business Logic**

Extract business logic into custom hooks:

```tsx
// useCompanyLogin.ts
export const useCompanyLogin = () => {
  const [isLoading, setIsLoading] = useState(false);
  
  const login = async (credentials) => {
    setIsLoading(true);
    // API call logic
  };
  
  return { login, isLoading };
};
```

### 4. **Barrel Exports**

Each module exports through `index.ts`:

```tsx
// components/ui/index.ts
export * from "./Button";
export * from "./Input";
export * from "./Card";

// Usage
import { Button, Input, Card } from "@/components/ui";
```

## File Naming Conventions

- **Components**: PascalCase (`Button.tsx`, `CompanyLogin.tsx`)
- **Hooks**: camelCase with `use` prefix (`useCompanyLogin.ts`)
- **Types**: PascalCase (`types.ts`, `common.ts`)
- **Utils**: camelCase (`helpers.ts`, `validators.ts`)
- **Constants**: UPPER_SNAKE_CASE in `constants.ts`

## State Management

### Local State
Use React hooks (`useState`, `useReducer`) for component-specific state.

### Global State
Use Redux Toolkit for:
- Authentication state
- Shared application data
- Cross-component communication

### Server State
Consider React Query or SWR for API data caching.

## Best Practices

### 1. **Component Composition**
```tsx
// ✅ Good: Compose small components
<Card>
  <CardHeader>
    <h2>Title</h2>
  </CardHeader>
  <CardBody>
    <JobTable data={jobs} />
  </CardBody>
</Card>
```

### 2. **Props Interface**
```tsx
// ✅ Always define prop types
interface ButtonProps {
  variant: "primary" | "secondary";
  onClick: () => void;
}
```

### 3. **Error Boundaries**
Wrap features in error boundaries for graceful failures.

### 4. **Code Splitting**
Use lazy loading for routes:
```tsx
const JobsPage = lazy(() => import("./pages/JobsPage"));
```

### 5. **Accessibility**
- Use semantic HTML
- Add ARIA labels
- Keyboard navigation support

## Testing Strategy

### Unit Tests
- Headless components (pure logic)
- Utility functions
- Custom hooks

### Integration Tests
- Feature components
- User flows

### E2E Tests
- Critical user journeys
- Authentication flows

## Development Workflow

1. **Create headless component** for reusable logic
2. **Create UI components** for design system
3. **Compose feature** using headless + UI
4. **Add to page** and test

## Example: Adding a New Feature

```bash
# 1. Create feature structure
mkdir -p src/components/features/JobCreate
cd src/components/features/JobCreate

# 2. Create files
touch index.ts JobCreate.tsx JobCreateForm.tsx useJobCreate.ts types.ts

# 3. Implement logic in hook
# 4. Compose with headless + UI
# 5. Export from index.ts
# 6. Use in page
```
